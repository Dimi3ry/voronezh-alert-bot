# Бот оповещений по Воронежу: БПЛА, ракетная опасность и отбой (`voronezh_alert_bot`)

Отдельный модуль (`src/voronezh_alert_bot`), который не затрагивает существующий новостной бот `voronezh_news_bot`. Предназначен для автоматической публикации срочных уведомлений в Telegram-канал через GitHub Actions.

## Какие события отслеживает бот

- 🚨 **Ракетная опасность** и 🟢 **Отбой ракетной опасности**
- ⚠️ **Опасность атаки БПЛА** и ✅ **Отбой опасности атаки БПЛА**
- 🔴 **Непосредственная угроза удара БПЛА** (сирены в Воронеже или конкретных районах области) и 🟡 **Отмена непосредственной угрозы БПЛА** (с пометкой, если общий режим опасности БПЛА в регионе сохраняется)
- ✈️ **Авиационная опасность** и 🟢 **Отбой авиационной опасности**

### Защита от ложных срабатываний и дублей

- Отсеиваются учебные тревоги, плановые проверки сирен, прогнозы погоды («опасность гололедицы», «выход на лёд») и итоговые/архивные статьи («итоги ночи», «последствия налёта», «главные новости»).
- Учитываются только события по **Воронежу и Воронежской области** (сообщения про соседние регионы отбрасываются).
- Ведётся состояние активных угроз и журнал публикаций в SQLite (`data/alert_bot.db`): если об одной и той же тревоге или отбое написали сначала `@gusev_36`, затем `@mchs36` и воронежские СМИ, в канал уйдёт **одно** сообщение от самого авторитетного/первого источника.

## Настройка и запуск в GitHub Actions

1. В репозитории откройте **Settings → Secrets and variables → Actions → Secrets** и добавьте **Repository secrets**:
   - `ALERT_TELEGRAM_BOT_TOKEN` — токен бота от `@BotFather` *(если не задан, используется `TELEGRAM_BOT_TOKEN`)*
   - `ALERT_TELEGRAM_CHANNEL_ID` — `@username` канала или числовой ID `-100...` *(если не задан, используется `TELEGRAM_CHANNEL_ID`)*
2. Убедитесь, что бот добавлен администратором в целевой канал с правом **Публикация сообщений (Post Messages)**.
3. *(Опционально)* Во вкладке **Variables** можно переопределить:
   - `ALERT_GEO_SCOPE`: `region` *(по умолчанию — Воронеж и вся область, с указанием конкретных районов)* или `city` *(только город Воронеж и общеобластные сигналы, без сирен сугубо по другим районам)*.
   - `ALERT_MAX_ITEM_AGE_MINUTES`: `120` (не отправлять сообщения старше N минут).
   - `ALERT_INITIAL_POST_LIMIT`: `1` (сколько свежих событий максимум отправить при первом запуске).
   - `ALERT_INCLUDE_SAFETY_MEMO`: `true` (добавлять короткую памятку по безопасности).
4. Проверьте, что в **Settings → Actions → General → Workflow permissions** включено **Read and write permissions** (для сохранения базы `alert_bot.db` в отдельную служебную ветку `alert-bot-state`, независимую от `bot-state`).
5. Откройте **Actions → Run Voronezh Alert Bot → Run workflow**:
   - сначала можно запустить `dry-run` (проверка без отправки в Telegram);
   - затем `seed` (отметить старые посты без публикации) или сразу `once`.
   - Далее workflow будет запускаться автоматически каждые 5 минут (`*/5 * * * *`).

> [!NOTE]
> У GitHub Actions минимальный шаг `cron` — 5 минут, при этом платформа иногда запускает расписание с задержкой в несколько минут. Для мгновенной реакции (раз в 30–60 секунд) в будущем бота можно запускать тем же модулем `python -m voronezh_alert_bot --once` по таймеру на сервере.
